# Astro Static Site — Stack Conventions

> **Do not edit this file per-project.** It contains shared stack conventions from the starter template. All project-specific config (site name, domain, locales, fonts, contact email) goes in `CLAUDE.project.md` — imported below and overriding this file where they conflict.

@CLAUDE.project.md

## Stack

- **Framework:** Astro 7+ (static output) on Cloudflare Workers (static assets) — **do NOT use Astro 6 or earlier**
- **TypeScript:** 6.x strict — **do NOT upgrade to TypeScript 7** until Astro's tooling supports it (~TS 7.1)
- **Styling:** Tailwind CSS v4. **Components:** Starwind UI v3 (Astro-native, zero React)
- **i18n:** Paraglide JS with Astro's built-in i18n routing
- **Contact form:** Worker API route + Turnstile + Cloudflare Email Service (`send_email` binding)
- **Animations:** Motion (vanilla JS) for scroll/spring/timeline effects; plain CSS for simple cases
- **Icons:** Tabler Icons via npm. **Images:** sharp at build time. **Analytics:** Cloudflare Web Analytics (cookieless, zone-level auto-injection)
- **Runtime & package manager:** Node 24 LTS (`.node-version`; `engines.node` ≥ 22.12 is Astro's floor). pnpm pinned via `packageManager` in `package.json` (currently 11.x — corepack picks it up locally; Workers Builds should honor it too, so check the pnpm version in the build log); bump the pin deliberately, never run with an unpinned pnpm. Build-script approvals in `pnpm-workspace.yaml` under `allowBuilds`.

## Hard Rules

- **Everything is self-hosted:** fonts in `public/fonts/` (never Google Fonts or any CDN), all JS/CSS bundled from npm at build time (never CDN tags). Only permitted external requests: Turnstile (`challenges.cloudflare.com` — cannot be self-hosted, and no SRI on purpose since Cloudflare rotates the script) and Web Analytics. The CSP in `public/_headers` blocks everything else — if you add a third-party resource, whitelist its domain there or it will not load.
- **No React, Vue, Svelte, or framework islands.** All components are `.astro` files; interactivity lives in bundled TS modules under `src/scripts/` (see Script Lifecycle below). **`define:vars` is banned** — ClientRouter does not re-execute identical inline scripts after navigation, so they silently die after the first nav. Pass server values via `data-*` attributes or `<script type="application/json">`. Alpine.js may be added only if a project genuinely needs reactive client state.
- **All project CSS in `global.css` must be wrapped in `@layer components`.** Tailwind v4 utilities live in cascade layers — any unlayered rule beats them regardless of specificity (`.hidden` stops hiding, `md:` variants get ignored). When a JS toggle must win unconditionally, set inline `style.display` instead of toggling classes.
- **All user-facing text goes through Paraglide** (`import * as m from "@/paraglide/messages.js"`, keys in `messages/{locale}.json`, `localizeHref()` for links). Never hardcode strings. Never edit `src/paraglide/` — it's generated.
- **Never commit secrets** — `wrangler.toml` `[vars]` is for non-secret config only; secrets go via `wrangler secret put`. `.env.example` gets placeholders only.
- Explicit error handling — no silent failures.

## Script Lifecycle (ClientRouter)

ClientRouter does **not** re-execute identical inline scripts after client-side navigation, and bundled modules run only once per session — a script that attaches listeners at top level works on first load and silently dies after any nav click. Therefore:

- All interactivity is a bundled TS module in `src/scripts/*.ts`, registered through `onPageReady()` from `src/scripts/lifecycle.ts` and imported with a plain `<script>import "@/scripts/foo";</script>` tag.
- `onPageReady(init)` runs `init(signal)` on initial load and after every navigation, aborting the previous signal first. Every `addEventListener` inside `init` must pass `{ signal }`; intervals/observers must be cleared on `signal` abort.
- Inside `init`, bail early (`if (!el) return`) when the current page lacks the component — the module runs on every page.
- See `src/scripts/contact-form.ts` for the reference implementation.

## Images

- Always Astro's `<Image>` from `astro:assets`, with `widths`/`sizes`: full-width `widths={[640, 1024, 1920]} sizes="100vw"`; half-width `widths={[480, 800, 1200]} sizes="(max-width: 1024px) 100vw, 50vw"`; grid items `widths={[400, 800]} sizes="(max-width: 768px) 50vw, 25vw"`.
- Source images in `src/assets/`; `public/` only for files that must not be optimized. Meaningful `alt` always (`alt=""` only if decorative).

## Contact Form

- Frontend `src/components/ContactForm.astro`, backend `worker/index.ts` (`/api/contact` — static assets never invoke the Worker; only non-asset paths reach it).
- Email via the Email Service `send_email` binding — no third-party provider. Sending domain must be onboarded to Email Service; recipient must be a verified destination address (free to send to your own verified addresses).
- **Required UI states:** `idle` → `sending` (submit disabled) → `completed`/`failed`, both end states with a "Send another message" button. `completed` clears the form; `failed` preserves values for retry. Reset Turnstile after every attempt (tokens are single-use).
- **Turnstile is required — never remove it.** Secret: `TURNSTILE_SECRET`. Build-time public key: `PUBLIC_TURNSTILE_SITE_KEY` — the build **throws** when it's missing (a keyless build ships forms that silently 403 forever); `cp .env.example .env` provides Cloudflare's test keys for local work.
- **Explicit Turnstile rendering only** — implicit (`class="cf-turnstile"`) stacks a duplicate widget per ClientRouter navigation. `api.js?render=explicit` is loaded once from `ContactForm.astro`; the module renders into `[data-turnstile-container]` with `action: "contact"` and resets by widget id.
- **Server-side verification checks more than `success`:** `action` must be `"contact"` and the token's `hostname` must be in the `TURNSTILE_HOSTNAMES` allowlist (`wrangler.toml` var; `localhost` only via `.dev.vars`).
- For per-project widget creation/secret provisioning, use the `cloudflare:turnstile-spin` skill (ships with the `cloudflare` Claude Code plugin — install it if the skill is not listed).

## Non-Obvious Files

- `src/styles/starwind.css` owns the Tailwind import, design tokens (`:root`/`.dark`), and font-family variables; `src/styles/global.css` is only for project-specific overrides (all wrapped in `@layer components`) — never add `@import "tailwindcss"` or tokens there.
- OG images auto-generate per blog post (Satori); the OG font is auto-detected as the first `.ttf`/`.woff` in `public/fonts/` — just drop the file. **It must cover the site's scripts** (e.g. Cyrillic) or OG titles render as tofu. Custom OG images go in `public/og/` + frontmatter `ogImage`.
- **Fetching fonts:** Google's css2 API serves *variable* fonts to modern user agents — one file per style/subset with `font-weight: 300 700` ranges. Parse the weight as value-or-range, dedupe downloads by URL, and emit `@font-face` with the range; naive per-weight parsing writes byte-identical files and every weight renders as the lightest cut.
- Default locale must match in `astro.config.mjs` (`i18n.defaultLocale`) and `project.inlang/settings.json` (`baseLocale`). In code, the single source of truth is `DEFAULT_LOCALE`/`LOCALES` in `src/lib/locale.ts` — **never hardcode `?? "en"` fallbacks**.
- `src/middleware.ts` must stay on Paraglide's `paraglideMiddleware()` wrapper — a bare `setLocale(context.currentLocale)` breaks `localizeHref()` during prerender (all links on non-default-locale pages resolve to the base locale).
- Any nav variant (mobile overlay/drawer) must include the `LanguagePicker`, not only the desktop bar. SEO hreflang URLs (incl. x-default) always go through `getRelativeLocaleUrl()` — never string concatenation (trailing-slash drift).
- Blog posts: `src/content/blog/{locale}/slug.md` (Markdown only — add `@astrojs/mdx` and widen the loader glob in `src/content.config.ts` before using MDX); `draft: true` hides from listings.
- `public/_headers`: `X-Frame-Options: DENY` — switch to `SAMEORIGIN` only if the site must frame itself.
- Cookie banner: not needed (stack is cookieless; Turnstile cookies are strictly necessary). Required only if a project adds third-party analytics, embeds, or pixels — then add it globally in `Layout.astro`.

## Starwind UI v3

Styled markup lives in `src/components/starwind/` (editable, 49 components pre-installed, import from `@components/starwind/<component>`); behavior comes from the `@starwind-ui/astro` runtime — never copy legacy v2 behavior scripts into components. Manage with `npx starwind@latest update --all` / `add <component>`; keep `@starwind-ui/astro` on 1.x (the v3 runtime). v3 API differs from older docs: events are `starwind:value-change`, overlay triggers use `targetId` (not `for`), `DropdownLinkItem` replaces `DropdownItem as="a"`, Combobox replaces `SelectSearch`.

## Commands & Deployment

```bash
pnpm dev              # Astro dev server (no Worker — /api/contact 404s here)
pnpm build            # Static build to dist/
pnpm check            # astro check — type-check .astro + .ts (keep at 0 errors)
pnpm preview:worker   # wrangler dev — full-stack local preview incl. contact API
pnpm deploy           # Build + wrangler deploy
```

- Production deploys via Workers Builds (build `pnpm build`, deploy `npx wrangler deploy`); all Worker config (assets, bindings, vars) is in `wrangler.toml`.
- **`wrangler.toml` `[vars]` is the single source of truth for runtime vars** — dashboard edits are overwritten by every deploy. `PUBLIC_`-prefixed build-time vars live in the **committed `.env.production`** (public by definition — never secrets), so Workers Builds needs zero dashboard build variables.
- **Canonical-host redirects (www→apex) are a zone Redirect Rule, never Worker code.** `run_worker_first` would route every static asset through the Worker (billable + slower), and an http→https check in the Worker loops under `wrangler dev` — HTTPS enforcement is the zone's "Always Use HTTPS" job.
- `wrangler dev` simulates the **first** entry of `routes[]` over plain http — keep the canonical apex first.
